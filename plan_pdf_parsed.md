## 1. Протоколы TCP и UDP

Современные сетевые программы обмениваются данными по
стандартизированным правилам – протоколам. Два главных протокола прикладного

```
TCP (Transmission Control Protocol) – надёжный протокол с установкой
соединения. Перед передачей данных стороны «договариваются» друг с другом, каждый
пакет подтверждается, потерянные пересылаются повторно. Это как заказное письмо с
уведомлением о вручении.

UDP (User Datagram Protocol) – быстрый протокол без установки соединения.
Пакеты отправляются без предварительных договорённостей и без подтверждения. Это
как листовка в почтовый ящик: быстро, но гарантий нет. В данной работе используется
UDP – он идеально подходит для широковещательных рассылок.

## 2. Сокеты в C#

Сокет – это программный интерфейс для сетевого взаимодействия,
предоставляемый операционной системой. Можно представить его как «сетевую
розетку»: программа «подключается» к ней и получает возможность отправлять и
принимать данные.


В C# работа с сокетами осуществляется через пространство имён
System.Net.Sockets. Для большинства задач не нужно работать с низкоуровневым
классом Socket напрямую – есть удобные классы-обёртки:

```
Класс Назначение
UdpClient Отправляет и принимает UDP-пакеты
TcpListener Ожидает входящих TCP-соединений (сервер)
TcpClient Подключается к TCP-серверу (клиент)
IPAddress Представляет IP-адрес (например, 192.168.1.10)
IPEndPoint Пара «IP-адрес + порт» – полный адрес участника
```
Порт – числовой идентификатор (0–65535), по которому операционная система
понимает, какой программе адресован входящий пакет. В данной работе используется
порт 8001.

## 4. Режимы адресации в UDP

```
При отправке UDP-пакета можно адресовать его по-разному.
```
**_Unicast – одному получателю_**
Пакет доставляется конкретной машине по её IP-адресу. Получает только она
одна.

```
client.Send(data, data.Length, "192.168.1.10", 8001);
```
**_Broadcast – всем в локальной сети_**

Пакет рассылается всем машинам в подсети. Специальный адрес 255.255.255.
означает «всем».

```
client.EnableBroadcast = true;
client.Send(data, data.Length, "255.255.255.255", 8001);
```
**_Multicast – группе подписчиков_**

Multicast – наиболее гибкий вариант. Создаётся виртуальная «группа» с
собственным IP-адресом. Пакет получают только те программы, которые явно вступили
в эту группу. Адреса multicast-групп зарезервированы в диапазоне 224.0.0.0 –
239.255.255.255. В данной работе используется адрес 235.5.5.1.

```
IPAddress group = IPAddress.Parse("235.5.5.1");
```
```
// Вступить в группу (начать получать её пакеты)
client.JoinMulticastGroup(group, TTL);
```
```
// Отправить пакет всем участникам группы
client.Send(data, data.Length, "235.5.5.1", 8001);
```
```
// Покинуть группу при выходе
client.DropMulticastGroup(group);
```
Параметр TTL (Time To Live) определяет, через сколько маршрутизаторов может
пройти пакет. TTL = 1 – только локальная сеть. В работе используется TTL = 20.

## 5. Кодировка строк

По сети передаются только байты, а не строки. Поэтому перед отправкой строка
преобразуется в байты, а после получения – обратно. Важно использовать одну и ту же
кодировку с обеих сторон:

```
// Перед отправкой: строка → байты
byte[] data = Encoding.Unicode.GetBytes("Продам велосипед");
```
```
// После получения: байты → строка
```

```
string text = Encoding.Unicode.GetString(data);
```
## 6. Структурированные сообщения

Часто нужно передать не просто строку, а несколько связанных данных: имя,
товар, цену. Для этого поля упаковываются в одну строку через символ-разделитель '|', а
на стороне получателя разбираются методом Split():

```
// Упаковка: несколько полей → одна строка
string packed = string.Join("|", "AD", "Иван", "Велосипед", "3000");
// Результат: "AD|Иван|Велосипед|3000"
```
```
// Распаковка: одна строка → массив полей
string[] parts = packed.Split('|');
string type = parts[0]; // "AD"
string name = parts[1]; // "Иван"
string title = parts[2]; // "Велосипед"
string price = parts[3]; // "3000"
```
Первое поле – тип сообщения. Это позволяет получателю сразу понять, что
пришло: объявление ("AD") или системное уведомление ("SYS").

## 7. Многопоточность в Windows Forms

Метод Receive() блокирующий: программа останавливается на нём до прихода
пакета. Если вызвать его в главном потоке формы – окно зависнет и перестанет
реагировать на действия пользователя.

Решение: запустить приём сообщений в отдельном фоновом потоке с помощью
Task:

```
Task.Run((Action)ReceiveMessages); // запустить метод в фоне
```
Но здесь возникает вторая проблема: в Windows Forms изменять элементы формы
(кнопки, списки, поля) можно только из главного потока. Попытка изменить их из
фонового потока вызовет исключение.

Для передачи действия в главный поток используется метод Invoke() с делегатом
MethodInvoker:

```
// НЕЛЬЗЯ – обращение к listBox из фонового потока:
listBox.Items.Add(message); // вызовет исключение!
```
```
// ПРАВИЛЬНО – передать действие в главный поток:
this.Invoke(new MethodInvoker(() =>
{
listBox.Items.Add(message); // выполнится в главном потоке
}));
```

## 8. Обработка исключений при закрытии

При закрытии формы метод client.Close() прерывает ожидание в Receive(), и
фоновый поток получает исключение ObjectDisposedException. Это штатная ситуация, а
не ошибка. Обрабатывается так:

```
catch (ObjectDisposedException)
{
// Если alive=false – сокет закрыт намеренно, завершаем поток
тихо.
// Если alive=true – это неожиданная ошибка, пробрасываем дальше.
if (!alive) return;
throw;
}
```
Важно: флаг alive устанавливается в false ДО вызова client.Close(), чтобы поток
правильно распознал ситуацию.

## Интерфейс приложения

```

## Требования

**1. Вход/выход.** По кнопке loginButton программа подключается к multicast-группе
    и запускает фоновый поток приёма. При входе всем рассылается системное
    сообщение «[имя] вошёл на доску объявлений». По кнопке logoutButton – «[имя]

**2. Публикация.** По кнопке publishButton формируется сообщение формата
    AD|имя|товар|цена и рассылается через multicast всем участникам.
**3. Приём и отображение.** Сообщения типа "AD" отображаются в adsListBox в
    виде «[время] Продавец: товар – цена руб.». Системные сообщения (тип "SYS")
    - в виде «→ текст».
**4. Блокировка кнопок.** До входа: кнопки publishButton и logoutButton
    недоступны, поле имени доступно. После входа: наоборот. После выхода –
    возвращается исходное состояние.
**5. Корректное завершение.** При закрытии формы, если пользователь в сети –
    автоматически выполняется выход с отправкой уведомления.
